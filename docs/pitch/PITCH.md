# Pitch — SnoozeOps

**Duración:** hasta 5 minutos. Todas las escenas, personas, descansos y saltos temporales son sintéticos.

| Tiempo | Mensaje y escena |
| --- | --- |
| 0:00–0:40 | Rodrigo rota turnos, tiene guardia y ya sabe que duerme poco. No necesita otro tracker: necesita decidir un cambio que no invente disponibilidad. |
| 0:40–1:20 | Declara una traba y la confirma manualmente. Mostrar que “ruido de construcción” no recibe una propuesta de cerrar tickets; la demo reconoce el límite. |
| 1:20–2:00 | Restaurar punto de bifurcación, aceptar la propuesta de cierre voluntario y explicar que no modifica alertas exigidas. |
| 2:00–3:00 | Simular “misma hora”: la tarjeta separa qué probamos, qué ocurrió y qué falta saber. Cambiar al mismo punto y simular “tardó en conciliar”: cambia la pregunta, no sólo la redacción. |
| 3:00–3:45 | Mostrar revisión: puede mantener la acción, proponer otra distinta para aceptación humana, pedir una aclaración o reconocer una restricción. |
| 3:45–4:30 | Abrir Registros y volver al ciclo. Explicar que sólo se comparan contextos compatibles y que borrar un registro invalida lo que dependía de él. |
| 4:30–5:00 | Cierre: el objetivo es validar si Rodrigo puede dormir una hora más; hoy demostramos una manera breve y honesta de aprender qué cambio merece probar. |

No dedicar el tiempo a arquitectura ni afirmar mejora clínica o causalidad.
